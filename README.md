A complete C-to-Miniforth compilation and execution system featuring a retargeted LCC compiler backend and a custom stack-based virtual machine.

## Overview

This project implements a complete toolchain that:

1. **Compiles C code** to Miniforth bytecode using a custom LCC backend
2. **Generates readable Forth** representation alongside binary object code  
3. **Executes bytecode** on a custom stack-based virtual machine
4. **Provides comprehensive testing** with 31+ stress test cases

## Quick Start Example

### 1. C Code Input

Let's start with a simple C function:

```c
/* tests/examples/simple_math.c */
int calculate_sum(int a, int b) {
    int result = a + b;
    return result;
}

int main() {
    return calculate_sum(15, 27);  /* Expected: 42 */
}
```

### 2. Compilation Process

Compile the C code to Miniforth bytecode:

```bash
# Using the LCC retargetable compiler with Miniforth backend
external/lcc/build/rcc -target=miniforth tests/examples/simple_math.c
```

### 3. Generated Bytecode Output

The compiler generates both readable Forth and binary object code:

#### Readable Forth Representation:
```forth
\ Function: calculate_sum
:calculate_sum
    \ int result = a + b;
    LOCAL_1 LOCAL_0 + LOCAL_2 !    \ result = a + b
    \ return result;
    LOCAL_2 @                      \ load result
    RET                            \ return value
;

\ Function: main  
:main
    \ return calculate_sum(15, 27);
    LIT 15                         \ push first argument
    LIT 27                         \ push second argument
    calculate_sum CALL             \ call function
    RET                            \ return result
;
```

#### Binary Object Code:
```
Miniforth VM Bytecode v1.0
Entry Point: main

0000: OP_LIT 0015    # main: push 15
0002: OP_LIT 0027    # push 27  
0004: OP_CALL 0008   # call calculate_sum
0006: OP_EXIT        # program exit
0008: OP_LOAD_LOCAL 1 # calculate_sum: load param a
0010: OP_LOAD_LOCAL 0 # load param b
0012: OP_ADD         # a + b
0013: OP_STORE_LOCAL 2 # store to result
0015: OP_LOAD_LOCAL 2 # load result
0017: OP_RET         # return
```

### 4. VM Execution

Run the bytecode on the Miniforth VM:

```bash
# Execute bytecode file
./vm simple_math.mf

# Or with debug output
./vm --debug simple_math.mf
```

## Compiler Architecture

This project features **two distinct C-to-Miniforth compilers**:

### 1. Custom Compiler (`src/compiler/` - 1,931 lines)
A purpose-built compiler designed specifically for the Miniforth VM:

**Strengths:**
- **Compact & Efficient**: Complete C-to-Miniforth compiler in just 1,931 lines
- **Purpose-built**: Optimized for Miniforth VM characteristics
- **Educational**: Clear 3-phase design (lexer→parser→codegen)
- **Fast compilation**: Minimal overhead, rapid build times
- **Clean output**: Direct, readable bytecode generation

**Architecture:**
- **lexer.c**: 404 lines - Tokenization and lexical analysis
- **parser.c**: 624 lines - Recursive descent parser with AST construction
- **codegen.c**: 409 lines - Direct bytecode generation from AST
- **symbols.c**: 226 lines - Symbol table and scope management
- **Headers**: 268 lines - Interface definitions

**Limitations:**
- Basic C subset only (no structs, limited pointers)
- No optimization passes
- Function calls not fully implemented

### 2. LCC Retargeted Backend (`external/lcc/src/miniforth.c` - 284 lines)
A professional compiler backend leveraging the mature LCC infrastructure:

**Strengths:**
- **Production Quality**: Based on battle-tested LCC compiler (58,891 lines)
- **Complete C89 Support**: Full C language specification
- **Proven Architecture**: LCC's retargeting approach is industry-standard
- **Advanced Features**: Structs, unions, function pointers, complete type system
- **Comprehensive Testing**: Successfully compiles all 31 stress test cases

**Code Efficiency:**
- **Backend**: 284 lines of Miniforth-specific code
- **LCC Infrastructure**: 58,891 lines of mature compiler technology
- **Total**: 59,175 lines for complete C89-to-Miniforth compilation

**Trade-offs:**
- Large binary size due to LCC front-end
- Complex integration requiring LCC knowledge
- Less customization flexibility

### Compiler Comparison

| Aspect | Custom Compiler | LCC Backend |
|--------|----------------|-------------|
| **Total Code Size** | 1,931 lines | 59,175 lines |
| **Language Support** | Basic C subset | Complete C89 |
| **Binary Size** | Small | Large |
| **Compilation Speed** | Fast | Moderate |
| **Code Quality** | Basic | Production |

## Architecture Overview

### Miniforth VM Instruction Set

| Instruction | Opcode | Description | Stack Effect |
|-------------|--------|-------------|--------------|
| `OP_LIT n` | 0x01 | Push literal value n | `( -- n )` |
| `OP_ADD` | 0x02 | Add top two values | `( a b -- a+b )` |
| `OP_SUB` | 0x03 | Subtract top from second | `( a b -- a-b )` |
| `OP_MUL` | 0x04 | Multiply top two values | `( a b -- a*b )` |
| `OP_DIV` | 0x05 | Divide second by top | `( a b -- a/b )` |
| `OP_MOD` | 0x06 | Modulo operation | `( a b -- a%b )` |
| `OP_EQ` | 0x07 | Test equality | `( a b -- flag )` |
| `OP_LT` | 0x08 | Test less than | `( a b -- flag )` |
| `OP_GT` | 0x09 | Test greater than | `( a b -- flag )` |
| `OP_CALL addr` | 0x0A | Call function at address | Stack varies |
| `OP_RET` | 0x0B | Return from function | Stack varies |
| `OP_JMP addr` | 0x0C | Unconditional jump | No change |
| `OP_JZ addr` | 0x0D | Jump if zero | `( flag -- )` |
| `OP_LOAD_LOCAL n` | 0x0E | Load local variable n | `( -- value )` |
| `OP_STORE_LOCAL n` | 0x0F | Store to local variable n | `( value -- )` |
| `OP_LOAD_GLOBAL n` | 0x10 | Load global variable n | `( -- value )` |
| `OP_STORE_GLOBAL n` | 0x11 | Store to global variable n | `( value -- )` |
| `OP_EXIT` | 0x00 | Halt execution | Program ends |

### VM Components

- **Stack Machine**: 1024-element data stack for operands
- **Call Stack**: 256-element return address stack  
- **Memory**: Local variables, global variables, and heap
- **Program Counter**: Tracks current instruction
- **Instruction Decoder**: Interprets Miniforth bytecode

### Complex Recursive Algorithm

```c
/* Tower of Hanoi - tests deep recursion */
void hanoi(int n, int from, int to, int aux) {
    if (n == 1) {
        move_count++;
        return;
    }
    hanoi(n - 1, from, aux, to);
    move_count++;
    hanoi(n - 1, aux, to, from);
}

int main() {
    hanoi(5, 1, 3, 2);  /* 5-disk Tower of Hanoi */
    return move_count;  /* Expected: 31 moves */
}
```

### Data Structure Implementation

```c
/* Stack-based calculator */
struct Stack {
    int data[20];
    int top;
};

void push(struct Stack* s, int value) {
    if (s->top < 19) {
        s->data[++s->top] = value;
    }
}

int pop(struct Stack* s) {
    return (s->top >= 0) ? s->data[s->top--] : 0;
}

int main() {
    struct Stack calc;
    calc.top = -1;
    
    push(&calc, 15);
    push(&calc, 27);
    int result = pop(&calc) + pop(&calc);
    return result;  /* Expected: 42 */
}
```

## VM Implementation Details

### Memory Layout
```
┌─────────────────┐ 0x0000
│   Code Segment  │ (Program bytecode)
├─────────────────┤ 0x1000  
│  Global Memory  │ (Global variables)
├─────────────────┤ 0x2000
│   Call Stack    │ (Return addresses)
├─────────────────┤ 0x3000
│   Data Stack    │ (Operand stack)
├─────────────────┤ 0x4000
│  Local Memory   │ (Function locals)
└─────────────────┘ 0x5000
```

### Execution Model
1. **Fetch**: Read instruction at program counter
2. **Decode**: Parse opcode and operands  
3. **Execute**: Perform operation on stack/memory
4. **Update**: Advance program counter

### Calling Convention
- Arguments passed on data stack
- Local variables allocated in local memory frame
- Return address saved on call stack
- Return value left on data stack

## Contributing

### Adding New Tests
1. Create test file in appropriate `tests/lcc_miniforth/` subdirectory
2. Follow naming convention: `descriptive_name.c`
3. Include expected return value in comments
4. Add to test runner in `justfile`

### Extending VM Instructions
1. Add opcode definition in `vm.h`
2. Implement instruction in `vm.c:execute_instruction()`
3. Update LCC backend in `external/lcc/miniforth/`
4. Add test cases for new instruction

### Performance Optimization
- Use `-O2` compiler flags for VM build
- Profile with `gprof` or `valgrind`
- Consider JIT compilation for hot code paths
- Implement stack caching optimizations

## Troubleshooting

### Common Issues

**Segmentation Fault in LCC**
```bash
# Check C syntax and simplify complex expressions
external/lcc/build/rcc -target=miniforth -v file.c
```

**VM Stack Overflow**
```bash  
# Increase stack size or reduce recursion depth
./vm --stack-size 2048 program.mf
```

**Bytecode Verification Errors**
```bash
# Inspect generated bytecode
just show-bytecode test_name
hexdump -C program.mf
```
